# 🚀 Local RAG System (Retrieval-Augmented Generation)

Это модульная система RAG, позволяющая конфиденциально взаимодействовать с вашими документами (PDF, DOCX) с помощью искусственного интеллекта. Система использует гибридный поиск (dense + sparse embeddings) и механизм Reranking для обеспечения максимальной точности ответов.

## ✨ Основные возможности

- **Гибридный поиск**: Сочетание семантического поиска (Dense Embeddings) и ключевых слов (Sparse Embeddings) для точного нахождения контекста.
- **Reranking**: Использование специализированной модели Cross-Encoder для переранжирования найденных фрагментов, что значительно повышает релевантность ответов.
- **Интерактивный UI**: Удобный и современный чат-интерфейс на базе **Chainlit** с поддержкой drag-and-drop загрузки файлов.
- **Прозрачность работы**: Отображение найденных фрагментов исходного текста прямо в правой боковой панели чата.
- **Мониторинг задержек**: Отслеживание метрик (latency) для каждого этапа (Retrieval, Rerank, LLM) в реальном времени.
- **Эксперименты**: Интеграция с **MLflow** для логирования параметров и результатов работы пайплайна.

## 🧠 Используемые модели (по умолчанию)

- **Dense Embeddings (Семантика):** Локальная HuggingFace-модель (например, `BAAI/bge-large-en-v1.5` или `intfloat/multilingual-e5-large`).
- **Sparse Embeddings (Ключевые слова):** BM25 / SPLADE через встроенный `SparseEmbeddingService`.
- **Reranker (Переранжирование):** Cross-Encoder модель `BAAI/bge-reranker-large` для валидации контекста.
- **LLM (Генерация ответа):** **Qwen 2.5 (14B)**, развернутая локально через Ollama.

## 🛠 Технологический стек

- **Интерфейс**: [Chainlit](https://chainlit.io)
- **Векторная БД**: [Qdrant](https://qdrant.tech) (работает локально в Docker)
- **Локальный LLM-сервер**: [Ollama](https://ollama.com)
- **Платформа трекинга**: [MLflow](https://mlflow.org)
- **Среда выполнения**: Python 3.12+ (оптимизировано под WSL2 / Linux / macOS)

## 📂 Архитектура проекта

Проект построен на строго модульной архитектуре:
- `src/services/`: Базовые компоненты (парсер документов, эмбеддеры, коннектор к Qdrant, LLM-сервис, реранкер).
- `src/pipelines/`: Логика связки и координации всех сервисов в единый RAG-пайплайн.
- `src/config/`: Управление конфигурациями и гиперпараметрами через YAML.
- `app.py`: Точка входа для веб-интерфейса Chainlit.

## 🚀 Быстрый старт

### 1. Подготовка окружения

Клонируйте репозиторий и создайте виртуальное окружение:

```bash
git clone <url_вашего_репозитория>
cd <название_папки>
python -m venv venv
source venv/bin/activate  # Для Linux/macOS/WSL2
# или
venv\Scripts\activate   # Для Windows
```

### 2. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 3. Настройка конфигурации

Скопируйте пример конфигурации и настройте его под ваши нужды (при необходимости измените размеры чанков или параметры подключения):

```bash
cp src/config/config.example.yaml src/config/config.yaml
```

### 4. Автоматический запуск (Рекомендуется)

В проект встроен скрипт автоматизации запуска `start.py` (или `run.py`). Он берет на себя всю рутину по управлению инфраструктурой:
1. Проверяет и запускает демон **Docker** (если он выключен).
2. Поднимает контейнер **Qdrant** через `docker compose up -d` и ждет его готовности.
3. Запускает фоновый сервер **Ollama** (`ollama serve`).
4. Проверяет наличие модели **`qwen2.5:14b`**. Если модель не найдена, скрипт автоматически начнет ее скачивание (~9 ГБ).
5. Запускает веб-интерфейс Chainlit.
6. **При выходе (Ctrl+C):** аккуратно останавливает все фоновые процессы и тушит Docker-контейнеры, очищая оперативную память компьютера.

Для запуска всей системы выполните одну команду:
```bash
python start.py
```

## 📊 Мониторинг и метрики производительности

### Задержки в интерфейсе
В конце каждого ответа в интерфейсе Chainlit система выводит точное время выполнения ключевых этапов:
- **Retrieval**: Время поиска релевантных документов в векторной базе Qdrant.
- **Rerank**: Время работы Cross-Encoder модели по переранжированию чанков.
- **LLM**: Время ожидания первого токена и генерации финального ответа.

### Логирование в MLflow
Все параметры пайплайна (размер чанков, overlap, топ-K для retrieval и rerank), а также итоговые задержки автоматически логируются. 

Чтобы открыть панель мониторинга и сравнить результаты разных конфигураций, запустите:
```bash
mlflow server --host 127.0.0.1 --port 5000
```
После этого перейдите в браузере по адресу `http://localhost:5000`.

## ⚠️ Ограничения текущей версии
- **Форматы файлов:** Автоматический потоковый инжест через UI полностью оптимизирован под текстовые форматы `PDF` и `DOCX`. Сканы и изображения без текстового слоя (картинки) требуют предварительной обработки через OCR.
- **Аппаратные требования:** Так как модель `qwen2.5:14b` и модели эмбеддингов работают локально, для комфортной скорости генерации рекомендуется наличие дискретной видеокарты с поддержкой CUDA (от 12 ГБ VRAM) или процессоров Apple Silicon (M1/M2/M3 Pro/Max с объединенной памятью от 24 ГБ).
